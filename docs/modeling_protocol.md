## First achievable objective

Forecast each channel's **mean-removed RMS in volts at the next observed burst**, after the current 1.6 s burst has completed. This is a measured continuous target for a future forecasting task, not a failure/damage label or a claim of RUL. Start with a per-channel persistence baseline (next RMS = current RMS); only then consider a small predeclared regularized regression model, after separate authorization. Success would mean better next-record measurement forecasts under the tested protocol, not better failure prediction.

Inputs may use only the completed current burst: current A/C RMS, temperature-above-room and measured speed/static load/dynamic peak. Additional current crest/kurtosis descriptors are optional candidates requiring a development-only decision before freezing. Do not use next-burst measured conditions, next-burst features, future temperature, final experiment length, postmortem defects, time-to-last-record, measurement IDs, timestamps, stop logs, warning flags or segment IDs as automatic model inputs. Current descriptors are available only at burst completion. Any command-before-acquisition prediction variant needs separately verified command availability; the present CSV does not establish it.

The primary objective is **next observed record**, not failure within a horizon or a fixed number of operating seconds. Changing conditions may make persistence or simple regression weak, but that can be measured without inventing health labels. Actual calendar availability and deployment feasibility remain conditional on resolving the CSV timestamp start/end meaning and ordinal association.

## Fixed data and pair rules before any fitting

1. Never join across experiments. Use one complete source burst as the feature window; no overlapping sliding windows or waveform concatenation.
2. Future pair eligibility is fixed by the existing acquisition rule: current and next rows must be in the same source acquisition segment (no intervening CSV interval >24 s). This removes four B01 transitions, one B02 transition and no B04 transitions; the corresponding raw records stay retained. Maximum candidate pairs before other validity decisions are 372/1114/1113 for B01/B02/B04, respectively. These are not operating-time labels. This offline eligibility rule uses observed arrival times only to decide scoring availability, never as predictor input. In deployment a forecast expires after the predeclared gap limit; report expired/unevaluable forecasts rather than silently evaluating only convenient cases.
3. A change from logged warm-up setpoints must be reported as a separate regime/transition stratum. Do not call warm-up healthy, and do not choose an early fraction as a healthy training baseline.
4. Keep all mathematically valid raw values, including nominal-range warnings. Freeze how invalid/missing features would be handled before a held-out check. Initial persistence needs finite RMS only. Any future learned imputation/scaling is fit on training data only. Preserve a primary as-recorded metric and predeclared quality-stratified reports; do not exclude difficult rows after viewing errors.
5. Record condition-support status using the unchanged measured bins. Do not rescale B04's speed/load or widen bins to avoid unsupported conditions. B04's physical operating interpretation must be resolved from independent source/acquisition evidence before treating it as a physically comparable model covariate. A contextual out-of-support prediction is not automatically a failure warning.

## Development, validation and final reserve

- **B02: initial fitting experiment**, once separately authorized. Its matched operating ranges and valid measurements support a first trial, but its stopped/continued trajectory and changed endpoint rule must be retained as data history, not used as target labels.
- **B01: independent development-validation run.** It has already guided feature design and cannot supply an unbiased final test claim. Report all eligible next-record errors and support/quality strata. Its ambiguous termination does not prevent evaluating a recorded-voltage forecast, but prevents meaningful RUL/failure evaluation.
- **B04: secondary development stress case**, not a source of manufactured matched conditions. Current context values have an unresolved near-twofold discrepancy; report as-recorded forecast behavior only with that caveat, or mark the context-dependent variant unevaluable until independent clarification. It must not be silently pooled with B02 training data because that would hide the measurement issue. It is not an untouched test run because it has now been explored.
- **B03: proposed held-out evaluation reserve**, unchanged from the prior declaration. Do not inspect its feature distributions, plots or model outcomes for selecting features, thresholds, corrections or hyperparameters. No real B03 source file was opened in the current assessment. Existing structural checks are not complete measurement validation and are not evidence of predictive performance.

Prefer a small fixed model specification over a broad search on this tiny number of development experiments. If comparing alternatives, keep the choice entirely within development; optional reversed B01/B02 fitting/validation is a robustness check, not another independent final test. Do not randomly split bursts: highly dependent records from the same bearing would cross partitions. Any internal temporal split must ensure no input/target dependency straddles the boundary: for a one-burst input and next-burst target, drop the boundary pair. Future extended lookbacks/horizons require purging every overlapping raw-record dependency and an appropriate time embargo, never merely shuffling feature rows.

Before B03 can be evaluated, freeze feature definitions/allowlist, model family and settings, training data, scaling/imputation policy, forecast availability, pair/gap rules, metric definitions, validity gates and reporting strata in a versioned protocol. An independent or blinded validity pass may then apply **predefined** rules only: required channels/shapes, real finite samples, exact documented rate/time grid and duration, schema/time order, checksums, documented units/calibration and a recorded association caveat. Any externally documented per-run conversion must be established without feature/outcome-driven correction. Do not inspect distributional ranges to choose favorable gates or change the model after this pass. If required measurement meaning cannot be established, report the reserve as not evaluable rather than selecting another hold-out or manufacturing corrections. User authorization and role updates are required before any actual evaluation.

## Metrics and claim limits

For a future authorized experiment, report per-channel **MAE and RMSE in V**, persistence performance and paired differences on exactly the same eligible records. Report each experiment separately, then an equal-experiment development summary if useful. Include counts of scored, expired, structurally invalid and unsupported forecasts, plus predefined warm-up, gap-adjacent and measurement-warning strata. These diagnostic flags are reporting metadata, not automatic predictors or health labels. No alarm threshold or failure metric is justified by a forecast-only target.

One held-out bearing experiment can provide one independent case study under this shared laboratory rig/protocol. Hundreds of correlated bursts do not become hundreds of independent bearings. Do not infer population generalization, calibrated failure probabilities, industrial false-alarm rates or RUL accuracy. Simple row-wise confidence intervals would ignore dependence; any within-run blocked uncertainty analysis remains conditional on that run and does not resolve the lack of independent experiments.

A failure/RUL objective requires a later, separately justified endpoint definition: channel, statistic, window, threshold, crossing/reset logic, intervention/censoring and an exposure/time basis. B01's contradictory endpoint, B02's changed crossing-count rule, B04's unspecified numeric stop limit and the uninspected reserve do not currently supply that contract. Do not substitute elapsed CSV time, sample count or the final record for operating time or a failure label.

## Frozen execution amendment: forecast-v1 (2026-10-23, before fitting)

The current user request authorizes this prototype. It supersedes the proposal-only status above and earlier statements in README, AGENTS and status that no modeling may begin. The original proposal remains as design history. It does **not** authorize opening B03. The executable specification is `configs/forecast_v1.json`; its SHA256 is stored in each artifact. No outcome-driven hyperparameter search or alternative feature selection is permitted in this milestone.

B02 alone supplies fitting pairs and all learned preprocessing. B01 is experiment-separated development validation, already involved in feature design, not a final unbiased test. B04 is a separate as-recorded stress case, never pooled for fitting; its global unresolved-context warning is displayed even when its local warning is false. B02 resubstitution results are explicitly optimistic diagnostics. These are only two reasonably compatible independent development runs, not thousands of independent bearings. We do not reverse-fit or refit after validation here.

The single model predicts the two-channel **increment** relative to current RMS: delta = next RMS minus current RMS. Its seven inputs are the completed current burst's A/C RMS, T1/T2 above ambient, measured speed, static load and dynamic peak. Current crest/kurtosis, commands, clocks, elapsed time, IDs, warning flags and segment IDs are excluded. Each input is standardized with the training-pair-source population mean and standard deviation (constant scale becomes 1). Center the training delta targets by their training mean. Fit W = (Z'Z + 10 I)^(-1) Z'(delta - mean_delta), with an unpenalized intercept mean_delta. Prediction is current RMS + mean_delta + standardized_current @ W. Alpha 10 is modest fixed shrinkage in standardized coordinates; it is a design choice, not selected by validation. No target scaling, imputation, output clipping or normalization beyond this training-only input standardization. Negative predictions are retained and counted.

Issue one forecast only after a full source burst is available. Persistence needs finite current A/C RMS; ridge needs all seven finite current inputs. Missing inputs produce explicit unavailable predictions, with no imputation or record deletion. Score a channel only if its prediction and subsequently observed target RMS are finite. Both models are compared on common eligible channel pairs; also report each model's available counts and failures. Keep all range-warning measurements in primary as-recorded metrics. Split reports by source/target warm-up, regime transition, sensor range, local warning, gap adjacency and training-condition support. Future flags are used only retrospectively for reporting, never issuance. A B04 context warning is an offline audit caveat, not an online fault.

The future row's arrival time is unknown at issuance. On arrival, settle the previous pending forecast only for 0 < next CSV time minus source CSV time <=24 seconds. Otherwise retain an expired unscored record; then issue a new forecast from the newly arrived burst. At a caller-provided clock > source time +24 seconds, explicit replay expiry is possible before another arrival. Exactly 24 seconds remains eligible. First rows have no previous forecast; final forecasts remain pending. Never bridge experiments, concatenate bursts or interpolate. No future gap duration or future operating context enters prediction. CSV timestamps are provisional clock proxies: ordinal CSV/MAT association, start/end meaning and timezone remain unresolved; this is not validated wall-clock deployment timing or operating time.

For support, keep the established half-open measured bins (250 rpm, 250 N static, 250 N dynamic peak), with warm-up separate. Count source observations in B02 fitting pairs only. A bin is supported at >=20 training source observations; show seen-but-sparse and unseen separately. Do not broaden bins. This is limited occupancy support, not proof that future transitions or joint thermal/vibration states are represented. B04 loaded contexts have no physical matched-condition claim. Support uses current source context only; next-context change may explain difficulty retrospectively, but is never input.

Report per-run, per-channel MAE = mean(abs(error)), RMSE = sqrt(mean(error^2)), signed error = observed - forecast, and skill = 1 - model_error/persistence_error on identical common pairs. Negative skill is worse. A zero persistence denominator makes skill undefined. Include scored, expired, pending, unavailable, unsupported, negative predictions and predeclared strata counts. No confidence interval treating bursts as independent. No tuning after unfavorable results.

Replay/dashboard show continuous forecast deviations without alarm thresholds. Measurement warnings and acquisition gaps are separate from deviations. A documented general-description 110 °C reference is a separate temperature-limit notice if measured T1/T2 >=110 °C, **not** a failure label, run-specific stopping criterion or calibrated safety alarm. B04's 60 °C switching policy is not such a limit. No deviation thresholds, failure metrics or RUL are implemented.

Artifacts record exact config, its hash, training table SHA256, software versions, training source IDs, preprocessing, coefficients and support counts. Save numeric JSON, never executable pickle. Evaluation/replay verify input table hashes against the frozen run ledger. No command reads raw data or any B03 path. A later B03 task requires separate authorization and a blinded, predefined measurement-validity pass before using frozen artifacts once. Freeze invalid-feature rules and support strata as above, verify log-specific units/calibration independently, and report not evaluable if meaning is unresolved. No refitting on B01/B04/B03, no threshold changes after B03, no run substitution. One reserve run establishes at most one laboratory case study.
