# FactoryGuard v0.4.0 — investigation-alert prototype and evidence assistant

This is the release-note source for the **post-v0.3.0** prototype. The existing
published v0.3.0 tag/release remains unchanged. A GitHub v0.4.0 tag/release is
**not yet created by this document**; pin it to a reviewed merged master commit,
not a development branch, after required checks pass.

## Included software

- The existing pinned, recorded-data B01/B02/B04 investigation dashboard
  (2,607 saved events, 432 model-comparison rows; no raw waveform publishing).
- Deterministic, evidence-traceable investigation alerts v2: residual, sustained
  level and supported operating-context signals; disjoint level confirmations;
  separate monitoring availability, episode state and assessment; persistent
  append-only journal, reset/acknowledgment boundaries and structured exports.
  Detection never requires an LLM.
- An optional **local** MCP retrieval → bounded context → generation assistant,
  with explicit offline fixtures and opt-in live generation. Evidence IDs,
  provenance, citation inspection and uncertainty disclosures are part of the
  investigation workflow. It is not hosted on the public static Pages site.
- Replay/API safeguards, including loopback Host verification and reset-scoped
  alert acknowledgments. Both have regression tests.
- An optional read-only, checksum-checked [forecast uncertainty diagnostic](../forecast_uncertainty.md).
  Its chronological empirical-coverage numbers are exploratory and do not
  constitute calibrated 90% prediction intervals or alarm thresholds.

## Recorded forecasting results (unchanged)

Reciprocal B01/B02 development comparisons selected exponential smoothing,
with 12.83% equal-run/channel MAE improvement over persistence. Saved direction-
specific evaluation settings and the separate final alpha=0.5 configuration
remain unchanged. This is **development selection performance**, not an
unbiased held-out evaluation, validated damage detection or production
reliability. B04 remains diagnostic with unresolved context scaling and **B03
remains sealed**.

## Supported platform boundaries

- Linux assistant: supported local prototype path, CI required.
- macOS assistant: locally verified at the PR #8 checkpoint; no macOS CI.
- Windows core/static build: CI required.
- Windows assistant: explicitly **unsupported/advisory** for this release.
  Its real MCP NumPy native import delay triggers the existing 15-second
  deadline; tests remain visible and unmodified.

Blocking check names: `test (ubuntu-latest)`, `test (windows-latest)`,
`assistant (ubuntu-latest)`. Windows assistant remains advisory only. Do
not equate an overall green workflow with a passing Windows assistant job.
Enforced required checks still need repository rulesets/branch protection,
which was absent at PR #8 closeout.

## Scientific and operational limits

No verified healthy reference, fault labels, false-alarm rate, sensitivity,
detection delay, damage onset, remaining life, calibrated failure probability
or safety alarm is established. Long active alert episodes and missing/limited
operating support remain visible. Correlated bursts do not become independent
by using disjoint scoring windows; nominal uncertainty bands have no guarantee.
Only synthetic and development checks were executed for alert behavior.
Prompt-injection robustness, independent human review, broad live-generation
answer quality and production security remain outside this prototype.

The public Pages deployment is static and may lag behind this release unless
its separately authorized deployment workflow is dispatched. The live AI
assistant requires a private local API key and is never embedded in Pages.
