# Run and reproduce the development release

## Environment and local workflow

Use CPython 3.12 with requirements-lock.txt for the tested versions;
requirements-campaign.txt adds CPU XGBoost 3.0.5 for the complete campaign/tests.
Install the lock, then `pip install --no-deps -e .`. The `factoryguard` command
aliases `python -m factoryguard.release`. Linux activation is `source
.venv/bin/activate`; Windows PowerShell is `.venv\Scripts\Activate.ps1`, or use
`.venv\Scripts\python.exe` directly when activation policy restricts scripts.
Release files explicitly use UTF-8. CI also sets PYTHONUTF8=1 for legacy tests.
OS peak-memory reporting returns null on Windows instead of blocking ingestion.
The lock targets Python 3.12; pyproject ranges are not a claim that all versions
have been tested. Pins are not wheel hashes: mirror/OS libraries remain limits.

Restricted Linux environments may need `MPLCONFIGDIR=/tmp/factoryguard-matplotlib`
and `XDG_CACHE_HOME=/tmp/factoryguard-cache`. Windows normally has writable user
caches. OPENBLAS_NUM_THREADS=1 and OMP_NUM_THREADS=1 improve timing comparability;
the campaign also limits threads internally. No CUDA/browser package is needed
for ordinary application use. Playwright is an optional browser-test dependency.

Follow README to create the 319 kB real-data demo and serve it locally. The
loopback-only API provides `/health`, `/api/meta`, `/api/state?run=B01`, and JSON
POST `/api/step` or `/api/reset` with `{"run":"B01"}`. State returns only revealed
observations. SQLite transactions persist cursor/events; restart restores them.
One cursor per run is shared locally: this is not a multiuser/live service.
Reset clears derived events/cursor, never observations. No uploads, raw path
parameters or arbitrary model loading are exposed through the API.

Portable HTML embeds computed events and requires no server after export. It has
no future-observation access boundary and no persistence; reveal is presentation.
Export uses a database clone without altering the user's cursor. Quality, gaps,
forecast differences, context differences and the general 110 °C reference stay
distinct. Only trust joblib artifacts generated by a trusted source.

## Full-data reproduction

The `extract` command streams existing B01/B02/B04 directories, exactly
377/1116/1114 bursts, and writes a config with absolute derived paths. It hashes
raw files before/after and refuses outputs inside raw storage. Set
FACTORYGUARD_RAW_ROOT for a custom dataset directory. There are no downloads.
To reuse verified feature tables, change only paths in configs/release_v3.json.
Ordinary development entry points reject B03 before opening it.

Campaign output includes pre-fit config/protocol/source hashes, versions, split
ledger, every trial/error, inner-selected outer pipelines, complete forecasts,
common/broad coverage, quality strata, selection and final artifact. B04 loads
only after selection. `audit` recomputes 192 fold boundaries/scaler statistics,
inner choices, 72 outer/stress artifact predictions and primary metrics without
fitting. `report` includes unsuccessful configurations. Old forecast-v1 and
selection-v2 reports remain historical. A final-source rerun is a reproducibility
check of the unchanged frozen campaign, not an expanded search.

Final smoothing alpha .5 needs no learned pooled coefficient/scaler fit. The
artifact records B01/B02 training-source provenance; its state starts fresh per
segment. Development views preserve out-of-run settings: .2 on B01, .5 on B02.
B04 shows B02's .2 stress artifact, with unresolved context interpretation.

## Release bundles

Git contains code, pins, configs, tests, compact results and the attributed demo.
Archives/raw files, joblib pipelines, SQLite, full ledgers, large HTML and images
remain under ignored reports/local/ or external storage. Prepare an internal
review bundle with:

```bash
python scripts/bundle_release.py --results reports/local/release-v3 --workspace reports/local/release-full --output reports/local/factoryguard-review.zip
```

The script packages only declared derived campaign/workspace files with hashes
and attribution. It never traverses raw storage. Share privately with the source
branch and lock; no release upload, visibility change or deployment occurs here.
Verify manifest hashes before using artifacts; load joblib only from a trusted
source. The standalone dashboard alone is sufficient for a browser walkthrough.

## Understanding the methods

Persistence repeats current RMS; smoothing averages current RMS with past state.
Ridge fits a linear relationship with a penalty against large coefficients.
Its Pipeline standardizes each input using only that fold's training rows, so
volts, °C, rpm and N have comparable penalty scales. Trees need no scaler.
Extra Trees averages shallow randomized trees. Histogram boosting and XGBoost
add small trees correcting previous errors; XGBoost also regularizes them.
Fixed iteration counts avoid any outer-run early stopping. Hyperparameters are
chosen only in chronological inner folds; train error is an optimistic diagnostic.

Direct models estimate next RMS; increment models estimate next minus current
then add current back. Recent changes and trailing-three statistics are causal,
reset at boundaries/gaps, and use observation steps rather than invented operating
seconds. Undefined descriptors retain missing values; no imputer is fitted.
Compare training/validation/outer columns in results.md: flexibility and low
training error did not guarantee transfer, especially for direct-target trees.

Completed-observation context is separate: current speed/load can select a bin
because it is already measured, whereas a forecast cannot use the next burst's
context. Reference quartiles include warnings and unknown bearing states. n≥20
is only a display support rule, not evidence of health or independent sampling.
